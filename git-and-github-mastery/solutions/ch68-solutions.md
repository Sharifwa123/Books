# Chapter 68 solutions

## Level 1
**1.1** User accounts, organization accounts and enterprise accounts. Only a user account can be signed in to; you cannot sign in to an organization.

**1.2** Read, Triage, Write, Maintain, Admin.

## Level 2
**2.1** (a) Read, (b) Write, (c) Maintain.

**2.2** No change for an outside collaborator: base permissions do not apply to outside collaborators. No downgrade for the member either: a higher level granted on a repository overrides the base permission.

## Level 3
**3.1** For example: a website team with Write on the website repository, a mobile team with Write on the mobile repository, a documentation team with Write on the documentation repository, and Read for everyone on the documentation repository, possibly through the base permission or through a team that includes all members.

**3.2** A single owner is a single point of failure: if that person is away or leaves, nobody can manage the organization's settings. The documentation recommends assigning multiple owners so that ownership continues.

## Level 4
**4.1** Benefits: shared ownership that does not depend on one person, roles and teams, policies, an audit log, several owners. Decisions first: the name, at least two owners, the base permission, the teams, the repository-creation policy, two-factor authentication and security defaults.

## Level 5
**5.1** The warning that anyone who has a deploy key's private key can read or write the repository even after being removed from the organization. The key should have been deleted or replaced when the person left.

**5.2** Plans, prices and quantities change. Read the current plans page for the account type; do not quote a book.
