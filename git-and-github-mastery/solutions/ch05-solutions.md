# Chapter 5 solutions

## Level 1
**1.1** A typical answer: `https://en.example.org/menu/cakes` → scheme `https`, host `en.example.org`, path `/menu/cakes`.

**1.2** The server produced the message; it responded that the page was not found (status 404). The browser, the client, displayed it.

## Level 2
**2.1** (a) client; (b) server; (c) client; (d) server (the laptop answers your requests while you are the client).

**2.2** Local: the photo on your phone, `http://localhost:8765/` (it names your own computer). Remote: the document in an online office suite, the page on `example.org`.

## Level 3
**3.1** Any accurate analogy is acceptable: for example "the internet is the postal network, and the web is one kind of mail service that runs on it; email is another".

## Level 4
**4.1** A good reply: the padlock means the connection is encrypted and that the server proved it owns the name in the address; it does not mean the owner is honest or that the site is safe. Check the exact spelling of the address and whether you reached the site through a link you trust; do not enter passwords unless you expected to log in.

## Level 5
**5.1** Check the spelling of the domain name first, then whether DNS can resolve it (does the name exist?), then whether the server is reachable. "Cannot be found" before any page appears usually means the name could not be turned into an address, or the server could not be reached, not that a page is missing.

**5.2** 404 means the server could not find that resource. Check whether `images/logo.svg` exists at that path relative to the page, and that the folder name and capitalisation match exactly (Chapter 2<!--ref:files-->).
