# Chapter 64 solutions

## Level 1
**1.1** Public: anyone can see the code. Source-available: the code can be read but the licence may forbid some uses. Open source: the code is public and the licence grants permissions to use, change and share it.

**1.2** Maintainer and contributor are roles; write access and admin are permissions.

## Level 2
**2.1** `Signed-off-by: Ada Learner <ada@example.org>`, with the name and email from your configuration.

**2.2** Typical answers: the README, `CONTRIBUTING.md`, the code of conduct, the community profile, the issues list.

## Level 3
**3.1** Read the rules; look at the issues; discuss a large idea; fork, clone and branch (`git switch -c`); make a small change and test; open a pull request; respond to review with further commits; accept the decision.

**3.2** For example fixing an unclear step in the README: it is small, easy to review and helps every later reader.

## Level 4
**4.1** Thank the maintainer, ask nothing further about the decision, and move on. You may keep your fork for your own use if the licence allows it, or look for another project.

## Level 5
**5.1** Check that the project's guide sets no waiting rule and that checks passed; wait a reasonable time; add one polite comment asking whether anything is needed from you; do not repeat it daily.

**5.2** `git commit --amend -s --no-edit`, and check that you have the right to submit the work under the project's rules. If the branch was already pushed, you will have to push the amended commit, which changes history (Chapter 27<!--ref:rebase-->).
