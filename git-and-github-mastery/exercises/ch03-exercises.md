# Chapter 3 exercises — Editors and Project Folders

Attempt each exercise before you open `solutions/ch03-solutions.md`.

## Level 1 — Guided

**1.1 Prepare your editor.** Install or open a code editor (see section 3.2.2). Open your `sharif-git-lab` folder in it, so its files appear in a side panel. Turn on line numbers. *Expected result:* you can see numbered lines when a file is open.

**1.2 Edit and reload.** Follow the *Try it* box in section 3.5.1: open `index.html` in a browser, change the heading text in your editor, save, and reload the page. *Expected result:* the change appears in the browser.

## Level 2 — Partially guided

**2.1 Kinds of file.** For each file in the Sunrise Bakery project, write down: text or binary, and source file, documentation or asset. Hint: the logo is an SVG file, which is a picture stored as text.

**2.2 Break it on purpose.** Copy `sunrise-bakery` to a folder called `sunrise-bakery-test`. In the copy, move `images` out of the project folder. Open `index.html` from the copy. Describe what you see and explain it using the idea of a relative path. Then delete the test copy. *Hint:* only delete the copy you created.

## Level 3 — Independent

**3.1** Write a short note (four sentences) explaining to a classmate why the `.docx` version of a report is a poor choice if you want to see line-by-line changes between versions.

## Level 4 — Professional scenario

**4.1** A small charity keeps its volunteer schedule in a word-processor document that six people edit. They ask whether they should keep it in Git. Recommend a format and a way of working, and name one thing that would still be better in a word processor.

## Level 5 — Troubleshooting

**5.1** A learner edits `style.css` in a word-processor program, saves it, and the website loses all its styling. What is the most likely cause, and how would you confirm and fix it?

**5.2** You change `menu.html`, save, and reload the page. Nothing changes. List three things to check, in order.
