# Appendix L — Learning Roadmap After the Book

The book gives you the foundations and a way to check what you read. The best next step is to **use these skills on real work**. This roadmap suggests an order; it recommends no product, course or vendor.

## L.1 The first month

1. Repeat the capstone (Chapter 77<!--ref:capstone-->) with an idea of your own, on GitHub this time, doing the "On GitHub" column of every step.
2. Contribute one small documentation fix to a project you use, following its `CONTRIBUTING.md` (Chapter 64<!--ref:oss-->).
3. Set up the security features on a repository you own (Appendix G).
4. Take the assessment again without notes (Chapter 81<!--ref:assessment-->).

## L.2 Months two to six

- **Read Git's own documentation** regularly, starting with the tutorial and the manual pages of commands you use (Chapter 35<!--ref:readdocs-->).
- **Read GitHub's documentation** for features your team uses, with the version for your plan selected.
- **Automate something real** with a workflow: tests, a linter, a release (Chapters 54<!--ref:actions--> to 60<!--ref:wfsec-->).
- **Review other people's pull requests**: it teaches more than writing your own (Chapter 46<!--ref:review-->).
- **Practise recovery** on a throw-away repository until it is calm (Chapter 79<!--ref:playbooks-->).

## L.3 Going deeper (choose by need)

| If you need... | Study |
|---|---|
| to understand Git's internals | Chapter 30<!--ref:objects--> again, then the "Git Internals" material in Git's own documentation |
| to maintain a large project | branching strategies, release management, governance (Chapters 50<!--ref:protect-->, 75<!--ref:platformextras-->) |
| to run infrastructure | the documentation of the platform you use; container basics (Chapters 71<!--ref:packages--> and 72<!--ref:deploy-->) |
| to work on security | supply-chain security, secret management, code review for security (Chapters 62<!--ref:ghsec--> and 63<!--ref:secpractice-->) |
| to teach others | pair with a beginner; use this book's exercises as a starting point |

## L.4 Habits that last

1. **Verify before you trust**: read the source, check the date, run the command.
2. **Write things down** in the repository, so that they are versioned and reviewed.
3. **Keep changes small.**
4. **Read the state before and after each step.**
5. **Be kind in reviews and in issues.**

## L.5 Keeping this book's facts current

GitHub changes faster than a book. Appendix N lists what was checked and what is open; the ledger names the source of each claim, so you can compare it with the current documentation. Where they differ, trust the current documentation.
